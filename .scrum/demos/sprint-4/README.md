# Sprint 4 のデモ
## ゴール
スプリントの終わりに、PO はモデルを N ターン自動で回して CSV を出し、同じシードなら出力が同じであることと、勝利・敗北の条件を満たしたターンでゲームが止まって結果が出ることを確かめられる。巨大な式のエラー文は、読める長さに収まる。

## 動かし方
```
bash .scrum/demos/sprint-4/demo.sh [コードのディレクトリ] [--rehearse]
```
- コードのディレクトリを省くと、リポジトリの直下のコードを動かす。
- 前提：Godot 4.7.1 が `~/.local/bin/godot` にあること。gdUnit4 が無ければ、場面 0 で `scripts/setup.sh` が導入する（`git`、`curl`、`unzip`、`sha512sum` が要る）。
- 所要時間：1 分ほど（setup が走る場合は、ダウンロードの分が増える）。
- 待つ場面は無い。`--rehearse` は受け取るだけで、動作は変わらない。
- 場面 2・3 を単独で動かすコマンド：
  ```
  godot --headless --no-header --path <コードのディレクトリ> -s res://src/auto_run/auto_run_main.gd -- --model=res://src/sample/town_model.gd --turns=30 --seed=1 [--out=ファイル]
  ```
- 既知の出力：場面 0 の `scripts/test.sh` の冒頭に、debugger ポートの `ERROR: The remote port number must be between 1 and 65535 ...` と `ERROR: Remote Debugger: Unable to connect to host '127.0.0.1:0'.` が出る。gdUnit4 のコマンドラインの仕様による既知の出力で、不具合ではない。これ以外に ERROR と WARNING は出ない。
- 場面 3 の `エラー：...` の行と、終了コード 2 は、誤った指定を渡したときの台本どおりの出力で、不具合ではない。`demo.sh` の終了コードには影響しない（終了コードが 0 だと、かえって「想定外」と表示する）。

## 後片付け
- 出力ファイルと一時ファイルは `mktemp -d` の下に作り、終了時に自動で消える。
- テストのレポート `reports/` は、`demo.sh` の開始時に無かった場合だけ、終了時に消す。
- `scripts/setup.sh` が入れたもの（`addons/gdUnit4/`、`~/.local/opt/godot/`）は、git の管理外のまま残る。不要なら手で消す。
