# Sprint 6 のデモ
## ゴール
スプリントの終わりに、PO は、ゲームが終わった後はモデルが一切変わらないことと、何千もの条件や巨大な式を持つモデルが上限で拒否されるか現実的な時間で回ることを確かめられる。アクションで範囲の外の値にしようとしても、ストックは範囲に収まる。

## 動かし方
```
bash .scrum/demos/sprint-6/demo.sh [コードのディレクトリ] [--rehearse]
```
- コードのディレクトリを省くと、リポジトリの直下のコードを動かす。
- 前提：Godot 4.7.1 が `~/.local/bin/godot` にあること。gdUnit4 が無ければ、場面 0 で `scripts/setup.sh` が導入する（`git`、`curl`、`unzip`、`sha512sum` が要る）。
- 所要時間：1〜2 分（場面 0 のテストが大半。場面 1・2 の測定は 合わせて 30 秒ほど）。
- 待つ場面は無い。`--rehearse` は受け取るだけで、動作は変わらない。
- 場面ごとに単独で動かすコマンド：`godot --headless --path <コード> -s res://demo/<名前>.gd`（場面 1：`freeze_demo.gd`・`condition_perf_demo.gd`、場面 2：`ops_limit_demo.gd`、場面 3：`action_range_demo.gd`）。
- 既知の出力：場面 0 の `scripts/test.sh` の冒頭に、debugger ポートの `ERROR: The remote port number must be between 1 and 65535 ...` と `ERROR: Remote Debugger: Unable to connect to host '127.0.0.1:0'.` が出る。gdUnit4 の仕様による既知の出力で、不具合ではない。これ以外に ERROR と WARNING は出ない。
- 場面 1 の `Locked`・「ゲームは終了している」、場面 2 の `Out of memory` は、台本どおりの拒否の出力で、不具合ではない。
- 変更前の時間は #37 の報告の測定値（約 4.2 秒）を表示する。スプリント計画の台本の「約3.2秒」は issue の値で、この環境の測定とは差がある。
- 変更前と変更後は、同じモデルでは比べられない。変更前のモデル（約 99 万命令）は、#45 の上限（10 万命令）で作れなくなったためである。変更後は上限に収まる最大の形で測る。

## 台本
| # | PO の操作 | 期待する結果 | PBI |
|---|---|---|---|

| 3 | 下限 0・上限 100 の食料（50）と範囲の無いお金に、`food = food + 1000` のアクションを適用する（`demo/action_range_demo.gd`） | アクションは成功し、食料は 100 になる。範囲の無いお金は 1050 に増える。減らす側では食料は 0 に止まる | #39 |

## 後片付け
- 一時ファイルは `mktemp -d` の下に作り、終了時に自動で消える。
- テストのレポート `reports/` は、`demo.sh` の開始時に無かった場合だけ、終了時に消す。
- `scripts/setup.sh` が入れたもの（`addons/gdUnit4/`、`~/.local/opt/godot/`）は、git の管理外のまま残る。不要なら手で消す。
